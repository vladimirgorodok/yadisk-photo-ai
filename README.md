# Диск Фото AI

**ИИ-поиск и сортировка фотографий на Яндекс Диске.** PWA и Android-приложение: найдите снимки по текстовому описанию, отметьте нужные, перенесите их в любую папку Диска, а агент группировки разложит фотографии по людям и сюжетам. В APK — отдельный модуль работы с файлами самого устройства: локальный ИИ-анализ, переименование файлов (по содержимому и по распознанному тексту на картинке) и безопасная синхронизация «Диск ↔ устройство» через «Менеджер».

Всё распознавание выполняется **локально на устройстве** — фотографии никуда не отправляются, кроме самого Яндекс Диска. Приложению нужен только OAuth-токен Яндекса.

- PWA: **https://vladimirgorodok.github.io/yadisk-photo-ai/**
- Репозиторий: **https://github.com/vladimirgorodok/yadisk-photo-ai**
- APK: раздел **Releases** (стабильные версии) или **Actions → Android APK** (артефакты каждой сборки)

## Возможности

- 🔍 **Поиск по описанию.** Запрос на русском переводится на английский и сравнивается с CLIP-эмбеддингами фотографий. Работает без сервера и без облачных ИИ-сервисов.
- 🖼 **Результаты с миниатюрами.** Порог похожести настраивается, результаты можно догружать порциями.
- ✅ **Выбор файлов.** Отдельные фотографии или все найденные сразу.
- 🗂 **Дерево Яндекс Диска внизу экрана.** Разворачивайте папки, выбирайте папку назначения, создавайте новые папки прямо из приложения.
- 📦 **Кнопка «Переместить».** Переносит выбранные файлы в выбранную папку. При совпадении имён добавляется суффикс `(1)`, `(2)`… либо файлы заменяются — по выбору.
- 👥 **Агент группировки.** Находит лица (face-api) и объединяет фотографии одного человека, а также раскладывает снимки по сюжетам через CLIP: собаки, кошки, природа, море, еда, транспорт, документы и др.
- 💾 **Локальный кэш.** Индекс, эмбеддинги и миниатюры лиц хранятся в IndexedDB, модели — в кэше браузера. Повторный анализ не нужен.
- 📱 **PWA + APK.** Устанавливается как приложение на телефон и компьютер; APK собирается в GitHub Actions.
- 📁 **Модуль «Устройство» (APK).** Сканирование папок телефона с теми же принципами поиска и разбора, что и для Диска: ИИ-анализ, поиск по описанию, выделение.
- 🗂 **Пять разделов по назначению.** «Диск» (поиск и группы), «Устройство», «Менеджер» (перенос файлов между Диском и устройством), «Переименование» (реестр функций) и «Настройки» — каждый экран делает своё дело.
- ✏️ **Переименование по содержимому (APK).** Модель подписей описывает каждое фото, переводчик переводит подпись на русский — приложение показывает миниатюры и предложенные имена по маске из настроек (по умолчанию `14.11.26 кот на диване.jpg`, дата настоящая — из EXIF); вы отмечаете нужные и переименовываете выделенные. Есть журнал с кнопкой «Отменить».
- 🔎 **Распознавание текста на картинке (APK).** ИИ находит в выбранной папке (включая подпапки) изображения с текстом, распознаёт его офлайн (Tesseract, русский + английский) и предлагает переименовать: `Найденный текст ДД.ММ.ГГ` — дата создания файла настоящая (EXIF дата съёмки, иначе дата файла), а не копирования или переименования.
- 🚚 **Менеджер (Диск ↔ устройство).** Очередь переноса и два направления: выбрать файлы на Диске → скачать на устройство, выбрать на устройстве → залить на Диск. Политика конфликтов, md5-проверка, пауза и возобновление после перезапуска.
- 🖱 **Действия на каждой миниатюре.** Кнопка «⋯» на карточке: свойства файла (путь, размеры, даты, md5, ИИ-данные, крупное превью), копирование, перемещение и удаление — для файлов Диска и устройства.
- 🎨 **Тема и маски в настройках.** Светлая/тёмная/системная тема и маска имени для каждой функции переименования: `{text}`, `{date}` (ДД.ММ.ГГ), `{dateiso}`, `{time}`, `{name}`.
- 🚚 **Синхронизация «Диск ↔ устройство» (APK).** Очередь «Трансфер»: скачать копии с Диска (оригиналы остаются), залить локальные файлы обратно — с проверкой md5 после передачи, политикой конфликтов и возобновлением после перезапуска. Удаление оригинала — только явной опцией после успешной проверки.
- 🔒 **Приватность.** Токен и результаты анализа не покидают устройство. Единственные внешние запросы — API Яндекс Диска и загрузка ИИ-моделей с Hugging Face.

## Быстрый старт (PWA)

1. Откройте **https://vladimirgorodok.github.io/yadisk-photo-ai/** в Chrome, Edge или Safari.
2. Перейдите в **Настройки → Подключение к Яндекс Диску**.
3. Подключите Диск одним из способов:
   - **OAuth**: укажите Client ID приложения Яндекса и нажмите «Подключить через Яндекс» (см. ниже, как зарегистрировать приложение);
   - **вручную**: вставьте OAuth-токен с правами на Диск.
4. Вернитесь на вкладку **Поиск** и нажмите **«Сканировать Диск»**. Первый раз скачаются ИИ-модели (~200–300 МБ), затем приложение проанализирует фотографии. Это может занять время — прогресс и кнопка отмены есть на экране.
5. Введите запрос, например «кот на диване» или «море и пляж».

### Установка как приложение

- **Android/Chrome:** меню браузера → «Установить приложение» / «Добавить на главный экран».
- **iOS/Safari:** «Поделиться» → «На экран “Домой”».
- **Desktop Chrome/Edge:** иконка установки в адресной строке.

## Подключение Яндекс Диска

### Вариант 1. OAuth-приложение (для PWA)

1. Откройте [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new) и создайте приложение.
2. Платформа — **Веб-сервисы**.
3. **Redirect URI** (должен совпадать символ в символ, включая завершающий `/`):

   ```
   https://vladimirgorodok.github.io/yadisk-photo-ai/
   ```

   Точное значение для текущей страницы всегда показано в настройках приложения — его можно скопировать кнопкой.
4. В разделе доступов включите **Яндекс Диск**:
   - `cloud_api:disk.read` — чтение;
   - `cloud_api:disk.write` — запись (перемещение и создание папок);
   - `cloud_api:disk.info` — информация о диске.
5. Скопируйте **Client ID** и вставьте его в настройках приложения.
6. Нажмите **«Подключить через Яндекс»** и разрешите доступ.

Токен сохраняется только в `localStorage` вашего браузера. Кнопка «Отключиться» удаляет его.

### Вариант 2. Ручной токен (универсально, нужно для APK)

1. Получите OAuth-токен Яндекса с правами на Диск. Удобный путь: подключите Диск в веб-версии (вариант 1), затем в настройках нажмите **«Показать» → «Копировать»**.
2. В APK откройте **Настройки → Ручной ввод OAuth-токена**, вставьте токен и нажмите **«Сохранить токен»**.

> В APK OAuth-редирект на `https://…github.io/…` не открывается внутри WebView, поэтому используйте ручной ввод токена. Токен можно получить на компьютере и перенести на телефон.

## APK

Готовые APK:

- **Releases** — файл вида `yadisk-photo-ai-<версия>-release.apk` (сейчас актуальный — `yadisk-photo-ai-1.2.1-release.apk`; подписан debug-ключом, устанавливается на телефон без настройки);
- **Actions → Android APK** — артефакты `yadisk-photo-ai-debug-apk` и `yadisk-photo-ai-release-apk` для каждой сборки.

Установка: скачайте APK на Android и разрешите установку из неизвестных источников. Это учебная сборка, **не для публикации в Google Play** (release-подпись debug-ключом).

### Разрешения для модуля «Устройство»

При первом открытии вкладки «Устройство» приложение запросит доступ «Файлы и медиа» (на Android 11 и новее — «Все файлы»). Он нужен, чтобы читать и переименовывать файлы в выбранных папках. Доступ выдаётся один раз через системные настройки; весь ИИ-анализ при этом работает офлайн, файлы никуда не отправляются.

### Сборка APK локально

Требуются Node.js 22+, JDK 21 и Android SDK (platform 36, build-tools 36).

```bash
npm ci
npm run build:android      # сборка веб-части с base=/
npx cap sync android       # копирование assets в Android-проект
cd android
./gradlew assembleDebug    # или assembleRelease
```

APK появится в `android/app/build/outputs/apk/`.

## Модуль «Устройство» (APK)

Вкладка **Устройство** работает с локальными файлами телефона по тем же принципам, что и вкладка «Поиск» с Диском.

### Локальный ИИ-анализ

1. Выберите папку (быстрые кнопки — DCIM, Pictures, Download… или введите путь вручную).
2. Нажмите **«Сканировать папку»**: приложение найдёт изображения, создаст миниатюры и посчитает CLIP-признаки — прогресс и отмена на экране.
3. Ищите по описанию: «кот на диване», «закат», «документы» — переводчик и CLIP те же, что для Диска.

Индекс хранится в отдельном сторе IndexedDB (`local`) и не пересекается с индексом Диска. Повторное сканирование неизменённых файлов не пересчитывает признаки.

### Переименование по содержимому

1. Раздел **«Переименование»** → функция **«По содержимому»** (или выделение в «Устройстве» → «Переименовать по содержимому»).
2. Скачиваются модели: подписи (`Xenova/vit-gpt2-image-captioning`, ~200–250 МБ) и переводчик en→ru (`Xenova/opus-mt-en-ru`, ~80 МБ) — один раз, с прогрессом.
3. Каждое фото получает подпись, она переводится на русский и превращается в имя по маске из настроек (по умолчанию `{date} {text}` → `14.11.26 кот на диване.jpg`). Имя можно править в поле ввода.
4. Отметьте нужные карточки → **«Переименовать выделенные»**. Существующие имена не затираются — добавляется `(1)`, `(2)`…
5. Кнопка **«↶ Отменить переименования»** возвращает прежние имена (журнал хранится в базе, до 300 записей).

### Распознавание текста на картинке (OCR)

1. Раздел **«Переименование»** → функция **«Текст на картинке»** → выберите папку → **«1️⃣ Собрать изображения»** (папка + подпапки).
2. **«2️⃣ Распознать текст»**: Tesseract (rus+eng, работает офлайн после первой загрузки словарей ~15–20 МБ) проходит по картинкам; изображения без осмысленного текста помечаются «текста нет» и не выбираются.
3. Для каждой картинки с текстом предлагается имя по маске (по умолчанию `{text} {date}` → `Договор 14.11.26.jpg`): найденный текст, пробел и **настоящая дата файла** — EXIF дата съёмки, иначе дата самого файла (не меняется при переименовании и не путается с датой копирования).
4. Имена правятся вручную, выделенные переименовываются — с журналом и кнопкой «↶ Отменить».

### Менеджер (Диск ↔ устройство)

Отдельный раздел с тремя вкладками: **«Очередь»** (состояние переноса, пауза, повтор, очистка), **«С Диска»** (браузер папок Диска → выделение → очередь скачивания) и **«На Диск»** (браузер папок устройства → выделение → очередь загрузки).

### Синхронизация «Диск ↔ устройство»

Вместо «перемещения» — **копирование с проверкой**, чтобы файлы не исчезали с Диска посреди обработки:

| Операция | Как работает |
| --- | --- |
| ⬇ **Скачать на устройство** (раздел «Менеджер» → «С Диска») | Копия выделенных файлов с Диска в папку устройства. Оригиналы остаются на Диске. Галка «удалить оригинал после проверки md5» даёт эффект перемещения — безопасно и явно |
| ⬆ **Залить на Диск** (раздел «Менеджер» → «На Диск») | Копия локальных файлов в выбранную папку Диска. После передачи md5 сверяется с Диском; при расхождении — автоматический повтор |
| Политика конфликтов | Пропустить / Переименовать `(1)` / Заменить — настраивается при загрузке и в настройках |
| Очередь | Задачи лежат в IndexedDB и **переживают перезапуск**; выполняются по одной, с Wake Lock (экран не гаснет). «Пауза» останавливается после текущего файла |
| Проверка | Скачивание сверяется с md5 Диска, загрузка — с md5 на Диске (самопроверка через `spark-md5`) |

## Как это работает

| Шаг | Технология |
| --- | --- |
| Сканирование Диска | REST API Яндекс Диска, постраничный обход папок |
| Миниатюры | подписанные `preview`-ссылки API, обновляются при истечении |
| Поиск по описанию | CLIP `Xenova/clip-vit-base-patch32` (ONNX/WebGPU/WASM) |
| Русский запрос | перевод `Xenova/opus-mt-ru-en`, затем CLIP |
| Файлы устройства (APK) | `@capacitor/filesystem` + разрешение «Все файлы», миниатюры в IndexedDB |
| Переименование по содержимому | подписи `Xenova/vit-gpt2-image-captioning` → перевод `Xenova/opus-mt-en-ru` → маска имени (настраивается) |
| Распознавание текста (OCR) | `tesseract.js` (rus+eng, офлайн после первой загрузки) → фильтр «есть текст» → маска имени с настоящей датой (EXIF → mtime) |
| Настоящая дата файла | EXIF `DateTimeOriginal`/`CreateDate` через `exifr`, иначе mtime файла (не зависит от переименования) |
| Копирование Диск ↔ устройство | `@capacitor/file-transfer` (нативный поток + прогресс), md5 через `spark-md5` |
| Лица | `@vladmandic/face-api` (tiny detector + landmarks + 128-мерные дескрипторы) |
| Группы людей | кластеризация по косинусной близости дескрипторов |
| Сюжеты | сравнение CLIP-эмбеддингов фото с текстовыми описаниями категорий |
| Хранение | IndexedDB (сторы `photos`, `kv`, `local`, `jobs`), Cache API для моделей |
| Мобильное приложение | Capacitor 8 + Android |

Все вычисления идут на устройстве. Серверная часть отсутствует.

## Приватность

- OAuth-токен хранится в `localStorage` (PWA) или в WebView-хранилище (APK) и отправляется только в API Яндекса.
- Фотографии не загружаются на сторонние серверы: приложение скачивает миниатюры с Яндекс Диска и обрабатывает их локально.
- Эмбеддинги, результаты распознавания лиц и миниатюры лиц лежат в IndexedDB на устройстве.
- ИИ-модели скачиваются с Hugging Face при первом запуске и кэшируются браузером.
- Кнопки «Отключиться» и «Очистить ИИ-кэш и индекс» удаляют локальные данные. На самом Диске операции выполняются только по вашей команде (перемещение, создание папки).

## Разработка

```bash
npm ci
npm run dev        # http://localhost:5173/yadisk-photo-ai/
npm run build      # production-сборка для GitHub Pages
npm run preview
npm run test:db    # регрессионный тест локальной базы (fresh/heal)
```

Структура:

```
src/
  lib/        API Диска, CLIP/переводчик/подписи, OCR, face-api, сканирование,
              файловая система устройства, очередь трансфера, кластеризация
  state/      состояние приложения и модуля «Устройство»
  components/ дерево Диска, сетка фото, диалоги (переименование, загрузка, трансфер)
  views/      Поиск, Группы, Устройство, Настройки
android/      Capacitor-проект + плагин StorageAccess (доступ «Все файлы»)
.github/      workflows: GitHub Pages и сборка APK
```

### Переменные и настройки сборки

- `vite.config.ts` — `base: '/yadisk-photo-ai/'` для GitHub Pages. Для APK используется `npm run build:android` (`--base=/`).
- OAuth Client ID задаётся пользователем в интерфейсе и не хранится в коде.
- Секреты в репозитории не требуются.

## Ограничения

- Поиск работает по **превью** фотографий, поэтому мелкие детали могут не находиться.
- CLIP ViT-B/32 — компактная модель: сложные смысловые запросы работают хуже, чем простые («кот», «море», «свадьба»).
- Группировка лиц — эвристическая кластеризация, без ручного обучения. Ошибки возможны; порог задаётся в коде (`clusterFaces`).
- Первый анализ большого Диска (десятки тысяч фото) занимает заметное время; сканирование можно отменить и продолжить позже — уже обработанные фото кэшируются.
- Модуль «Устройство» доступен только в APK: браузер не даёт доступа к файловой системе (PWA показывает подсказку).
- Подписи ИИ могут быть неточными — имена всегда можно поправить вручную до переименования. Форматы, которые WebView не декодирует (некоторые HEIC), попадают в индекс без миниатюры и подписи; в OCR они помечаются «формат не декодируется» (распознаются JPEG/PNG/WebP и то, что умеет canvas).
- «Пауза» в «Трансфере» останавливает очередь после текущего файла: нативная передача не отменяется на лету.
- APK собран с debug-подписью и не предназначен для магазина приложений.
